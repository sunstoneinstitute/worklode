The walk

Four people carry this story: Tomas Lind (reporter), Ingerid Solheim (data scientist, lead), Dr. Anaya Rao (science lead) and Marit Holt (editor). Those four role names are already the vocabulary Worklode stores for a project's crew.

1

Discovery

Tomas pitches the story
By convention

What happens

Tomas has been reading Mattilsynet's waterworks reports and files a pitch: PFAS shows up in 41 of 356 municipal systems, and 12 are over the EU limit of 0.5 µg/L.

The pitch is one task in a standing INTAKE project that every candidate story lands in.

What he runs

# once, by an admin
lode project add intake \
  --name "Story intake" --key INT

# the pitch
lode task add --project intake \
  --kind design --priority high \
  --title "PFAS in Norwegian tap water" \
  --body-file pitch.md
lode task assign INT-41 --to tomas

What Worklode holds

  • Task INT-41, kind design, state draft
  • Author, timestamp and every later edit in the event log
  • Source links and images uploaded with the body, so they survive
  • Assigned to a human actor, the same way an engineering task is
Convention There is no intake surface. The cockpit's /intake and /ideas pages are placeholders, and a project has no seeded_by field. A standing project full of tasks does the job: pitches are listable, assignable and rankable on day one. What it does not give you is a capture form a reporter would use without being taught the CLI.
2

Selection

Ingerid and Tomas build the dossier
By convention

What happens

The pair works the pitch into a Selection dossier: the bounded question, the strongest evidence, the evidence against, and what is still unknown.

The dossier is a document, not a task body, so it gets revisions, an addressable id, and a review that names the revision it covered.

What they run

lode doc new --project intake \
  --kind spec --slug pfas-dossier \
  --file dossier.md

# revise until it holds
lode doc revise INT-SPEC-4 --file dossier.md
lode doc versions INT-SPEC-4

What Worklode holds

  • Document INT-SPEC-4, status draft
  • Every revision, diffable, with lode doc versions
  • Sections addressable as INT-SPEC-4 §2 in a review
  • lode show and /docs render it for anyone
Convention A dossier is filed as kind spec. Documents come in three kinds — spec, ADR and plan — and a Selection dossier is none of them. Spec is the honest fit: it is the design of the investigation, and it earns the revision history and the section anchors that a task body does not have. The word on screen will say "spec" until the kind vocabulary grows.
3

Editorial Evaluation

Marit and Anaya decide
Has a gap

What happens

The gate. The editor and the science lead each have to say yes on a named revision of the dossier before the story becomes a project.

Passing the gate promotes the dossier into an investigation project with its own key.

What they run

lode doc submit INT-SPEC-4   # asks for review

# each reviewer, after reading:
lode doc accept INT-SPEC-4

# promotion, by hand
lode project add pfas \
  --name "Forever chemicals in \
    Norwegian tap water" --key PFAS

What Worklode holds

  • doc submit records a review event and mints review tasks
  • Status moves draft → accepted, one acceptance
  • The new project PFAS, with no repo attached
Gap Two approvals cannot be required, and promotion leaves no trail. The approvals table is built and the /reviews page decides them, but the only rows anything writes are pull requests — a document cannot be sent for approval yet. So "both the editor and the science lead approved revision 5" is today two people agreeing in a meeting, and lode doc accept takes one assignee's word for it. Nothing links the new PFAS project back to INT-41 either.
4

Research

The crew works
Works today

What happens

The crew is named, the analysis repo is attached, and the work runs the way engineering work already runs: tasks, worktrees, pull requests, agents where they help.

The methodology is drafted as a document alongside the code that produces the numbers.

What they run

lode project crew add pfas ingerid \
  --role data-scientist --lead
lode project crew add pfas anaya \
  --role science-lead
lode project crew add pfas marit --role editor
lode project crew add pfas tomas --role reporter

lode project add-repo pfas \
  --repo sunstone/pfas-no-analysis

lode task add --project pfas --kind design \
  --title "Sampling and exclusion method"

What Worklode holds

  • A crew roster with real roles, one lead, one optional deputy
  • Tasks claimable into worktrees by a person or an agent
  • PRs, checks and merges correlated back to the task automatically
  • Agent sessions priced per task, so the story has a cost
  • The methodology as PFAS-SPEC-1, revisable and reviewable
Convention Grouping is a parent task. Milestones do not exist — there is no table and lode show --milestone says so out loud. Until they land, "internal review" and "publication" are two ordinary tasks with the stage's work filed under them via lode task parent --under. Everything else in this stage is the backbone doing what it was built for.
5

Report

Anaya, the buddy and the expert review
Has a gap

What happens

The project declares what it ships — the dataset, the reproducible analysis, the methodology and the report — and each one has to be shown to exist before the story can move on.

The data pipeline reports the dataset itself. Nobody ticks a box to say it is there.

What they do

# in the cockpit:
# /projects/pfas/deliverables/new
#   name  Dataset — municipal PFAS 2019–2025
#   url   ds:pfas-no@2025-07

# the pipeline, on registration:
POST /hooks/catalog   (signed)

What Worklode holds

  • Deliverables PFAS-DEL-1..4 on the project page
  • Artifact evidence against the declared address, from an emitter
  • State reported, never asserted by someone closing a task
Gap The review matrix is the missing piece. Deliverables are real and their state arrives from the catalog, but the reviews that make a report publishable have nowhere to live: approvals still only cover pull requests, so "buddy, domain expert and journalist have signed off on report rev 7" is not a query. There is also no lode deliverable verb — declaring one is a web form only — and no address that nothing pushes about is ever checked.

To be walkable by 1 September

Stage 4 already works. The shortest path to a walk a data scientist and an editor can complete without being coached through it, in the order that unblocks the most.

  1. LargestLet a document be sent for approval The approvals table already takes any entity_kind; its migration says so. Writing doc rows and widening the /reviews join is what turns the editorial gate from a meeting into a record, and it is the same change stage 5 needs for deliverables.
  2. SmallSeed the intake project and write the two body templates A pitch template and a dossier template, so the first thing a reporter meets is a form to fill in and not a blank file.
  3. SmallAdd lode deliverable add and list The API and the web form exist; the CLI verb is the missing mirror, and it is what lets the walk be scripted for a rehearsal.
  4. SmallName the promotion link Until seeded_by exists, a one-line convention: the new project's first task references the intake task id, so the trail is at least greppable.
  5. RehearsalWalk it once, end to end, with the real four people Before 1 September, on the real instance, with this story. Every step that needs explaining out loud is the next thing to fix.

What this mockup is. A proposal for how stages 1 to 5 run on Worklode as it stands on 27 August 2026, put up for the checkpoint so the conventions can be argued with before anyone builds on them. The commands were read out of the CLI, and the gaps out of the migrations.

What it is not. It is not spec 029. Milestones, deliverable-level approvals and the intake store are that spec's work and stay out of scope here. It is also not the cockpit redesign — that mockup already exists, one directory over, and shows the interface these conventions are a stopgap for.
