# Cockpit templ + HTMX + Tailwind Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the cockpit's `html/template` rendering and hand-written
stylesheet with typed `templ` components and a standalone Tailwind CSS v4 build,
and embed self-hosted HTMX as dormant substrate — preserving every rendered
markup semantic and every §10 accessibility outcome, and keeping `go build` and
`go test` free of any new tool.

**Architecture:** Pages stay server-rendered from the same `assemble*` functions
the JSON API uses. `internal/api/templates/*.html` become `*.templ` components
that render the identical semantic markup; `web.go` renders them with
`component.Render(ctx, w)` instead of `ExecuteTemplate`. The stylesheet is
generated by the Tailwind v4 standalone CLI from `assets/app.tailwind.css` into
the same served path `assets/app.css`. templ's `*_templ.go` and the built
`app.css` are committed and marked generated, so the existing single-binary
build needs no new tool; CI regenerates and fails on drift. HTMX is embedded and
referenced from the shell but carries no behavior.

**Tech Stack:** Go 1.26, `templ` (go.mod tool dependency), Tailwind CSS v4
standalone CLI (no Node.js, no PostCSS), self-hosted HTMX, `net/http`, embedded
static assets, the existing Go e2e harness.

## Global Constraints

- Server-rendered only. Pages are assembled from the existing `assemble*`
  functions — presentation logic keeps one source of truth. Add no client state
  and no second render path.
- Preserve rendered markup semantics exactly. Every existing web, cockpit, and
  e2e test asserts on the HTML; templ output must keep `<html lang="en">`, the
  skip link `href="#main-content"`, `<nav aria-label="Primary">`, exactly one
  `<main id="main-content">`, `aria-current="page"`, all headings, all visible
  copy, all `href` targets, and `href="/assets/app.css"`.
- §10 outcomes are non-negotiable: WCAG 2.2 AA, keyboard operability, visible
  focus (`:focus-visible`), no colour-only meaning, minimum 44px pointer
  targets, and the `@media (max-width: 64rem)` narrow-column layout.
- The built stylesheet must still contain the approved contrast-safe palette —
  `#0E1937`, `#F4F4F4`, `#FAD604`, `#266680`, `#46C5DE` — plus
  `prefers-color-scheme: dark` and the `[data-theme]` light/dark overrides. Fonts
  stay self-hosted: DM Sans for interface text, Source Serif 4 for headings.
- Self-host every asset (fonts, stylesheet, HTMX). No third-party CDN and no
  Node.js enter the build or the served page.
- Generated artifacts — `internal/api/*_templ.go` and
  `internal/api/assets/app.css` — are committed and marked generated in
  `.gitattributes`. `go build ./...` and `go test ./...` MUST succeed with
  neither templ nor Tailwind installed.
- templ generator and runtime versions MUST match; pin both in `go.mod`.
  Tailwind is pinned by version and sha256 under `scripts/`.
- The stylesheet build is not minified, so the accessibility contract test
  asserts readable strings. Minification is a deferred follow-up, not part of
  this plan.
- HTMX is embedded but dormant: no `hx-*` attributes and no behaviors. All
  interactivity is spec 032 §11's scope, out of scope here.
- Add no migration and no web mutation. Existing `webAuth` behavior, including
  open development mode when no provider is configured, is unchanged.
- Before claiming completion run: `go generate ./...`, `go build ./...`,
  `go test ./... -count=1`, `go vet ./...`, `go test -race -count=1 -tags e2e
  ./e2e/`, `./scripts/check-generated.sh`, and `./scripts/secfmt.py -l`.

- [ ] **Step 3: Write the Tailwind fetch script**

Create `scripts/fetch-tailwind.sh`. It reads the pinned version and checksums,
resolves the host platform, downloads once, verifies sha256, and installs to
`bin/tailwindcss`:

```bash
#!/usr/bin/env bash
# Fetch the pinned Tailwind CSS v4 standalone CLI into bin/, verifying sha256.
# Idempotent: re-running with the binary already present and correct is a no-op.
set -euo pipefail
cd "$(dirname "$0")/.."
source scripts/tailwind.sha256   # sets TAILWIND_VERSION and SHA256_<platform>

case "$(uname -s)-$(uname -m)" in
  Darwin-arm64)  plat=macos-arm64;  sum="$SHA256_macos_arm64" ;;
  Darwin-x86_64) plat=macos-x64;    sum="$SHA256_macos_x64" ;;
  Linux-x86_64)  plat=linux-x64;    sum="$SHA256_linux_x64" ;;
  Linux-aarch64) plat=linux-arm64;  sum="$SHA256_linux_arm64" ;;
  *) echo "unsupported platform: $(uname -s)-$(uname -m)" >&2; exit 1 ;;
esac

mkdir -p bin
if [ -x bin/tailwindcss ] && echo "$sum  bin/tailwindcss" | shasum -a 256 -c - >/dev/null 2>&1; then
  exit 0
fi
url="https://github.com/tailwindlabs/tailwindcss/releases/download/${TAILWIND_VERSION}/tailwindcss-${plat}"
curl -fsSL "$url" -o bin/tailwindcss
echo "$sum  bin/tailwindcss" | shasum -a 256 -c -
chmod +x bin/tailwindcss
```

- [ ] **Step 4: Pin the Tailwind version and checksums**

Set `TAILWIND_VERSION` to the current Tailwind v4 release. Download each
platform binary once, compute its sha256, and write `scripts/tailwind.sha256`:

```bash
TAILWIND_VERSION=v4.1.0   # replace with the current v4 release tag
for p in macos-arm64 macos-x64 linux-x64 linux-arm64; do
  curl -fsSL "https://github.com/tailwindlabs/tailwindcss/releases/download/${TAILWIND_VERSION}/tailwindcss-${p}" -o "/tmp/tw-${p}"
  printf '%s\n' "SHA256_${p//-/_}=$(shasum -a 256 "/tmp/tw-${p}" | cut -d' ' -f1)"
done
```

Write the results into `scripts/tailwind.sha256` as shell assignments, e.g.:

```bash
TAILWIND_VERSION=v4.1.0
SHA256_macos_arm64=<hash>
SHA256_macos_x64=<hash>
SHA256_linux_x64=<hash>
SHA256_linux_arm64=<hash>
```
