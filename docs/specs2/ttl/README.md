# Clause graph (proposal)

Turtle rendering of docs/specs2/01..11 as clauses (12-spec-refactoring-design-tree.md Q12 to Q20,
recommended answers). Generated by a script, not hand-maintained; the `constrains` and
`conflictsWith` edges are the only hand-added part.

## Rule applied

A clause is the lowest heading unit (H3 where present, else H2, plus the text between an H2 and its
first H3 as an "H2 preamble" clause, plus the text before the first H2 as clause `NN-0`). Tokens are
words * 1.3. The 800 ceiling used here predates S7 (the ceiling is now the configured embedding window, `LODE_EMBEDDING_CONTEXT_TOKENS`); a regeneration should read it from config. A leaf over 800 tokens splits at paragraph boundaries into parts `-a`, `-b`, ...; a leaf
under 100 folds into the previous clause of the same H2 unless it is a table or has no predecessor.
`## Sources` is skipped. Each `## Open questions` bullet is a `wl:OpenQuestion`. Headings inside
fenced code blocks are text, not headings. Clause id: `<docnum>-<h2>-<h3>[-<part>]`.

## Known ugliness

- `01-system-and-deployment.md` Glossary is a single table over 800 tokens; a table cannot split at a
  paragraph boundary, so `01-<n>-b` stays at 949 tokens.
- Sub-100 clauses that survive are tables or the first leaf in their H2 (nothing earlier to fold into).
- Bare `§N` pointers are resolved to the same document; a `§N` naming an H2 that has only H3 children
  resolves to that H2's first clause.
- `constrains`/`conflictsWith` were added only around the clauses with most inbound references
  (03 §5, §7, §8; 05 §5, §6, §10, §11.2, §15; 11 §3, §5).
